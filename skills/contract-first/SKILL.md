---
name: contract-first
description: 仕様があいまいな API やデータ形式を、実装前に確定・未確定・仮定へ分ける。仕様が不足しているとき、聞き取りの結果を渡されたときに使う。
---
1. 課題文、コード、利用者から渡された回答だけを根拠にする。
2. `docs/contract.md` を作るか更新する。表の列は「項目／内容／状態（確定・未確定・仮定）／根拠」。
3. 見る項目: 経路とメソッド、入出力の型、状態コード、エラー形式、境界値、丸め、順序、重複、同時実行、永続化。
4. 未確定は結果への影響が大きい順に挙げる。質問文は利用者が書くので代筆しない。
5. 回答が来たら該当行だけ更新し、矛盾があれば指摘する。
